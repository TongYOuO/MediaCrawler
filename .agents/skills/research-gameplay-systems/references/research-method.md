## 1. 研究对象与证据规则

玩法调研需要同时完成三件事：理解设计、支持竞品判断、提炼可迁移原则。使用同一条因果链组织材料：

```text
体验承诺 ← 玩家行为 ← 核心决策 ← 规则/反馈/资源 ← 前置条件与生产支撑
```

### 1.1 写可证伪问题

弱问题：“这个游戏有哪些武器？”

强问题：“游戏怎样促使玩家主动换武器，而不是找到支配策略后一直使用？”

将命题写成：

> 在【条件】下，系统通过【规则/反馈】促使【目标玩家】做出【行为】，产生【体验】；若观察到【反证】，修改该解释。

### 1.2 区分五类证据

| 标签 | 含义 | 记录要求 |
|---|---|---|
| `游戏直接观察` | 在指定版本和场景中亲自观察 | 平台、版本、时间点、前置状态、复现步骤 |
| `开发者直接主张` | GDC、访谈或补丁中明确表达 | 原文件、页码/时间戳、原始语境 |
| `外部来源转述` | 攻略、Wiki、评测、评论 | 日期、作者、URL、能支持的最大范围 |
| `跨来源综合推论` | 两条以上证据推导出的解释 | 推导链、替代解释和反证 |
| `待验证假设` | 合理但仍可能被推翻 | 反证条件和下一步验证 |

证据类型不等于置信度。一次直接观察可能是偶然个案；开发者陈述能证明设计意图，却不能自动证明所有玩家都获得了预期体验。

### 1.3 最小证据账本

每条主张记录：

- Evidence ID
- 原子化主张或观察
- 证据类型
- 游戏版本、平台、玩家阶段和场景
- 来源 URL、截图、录像时间戳或页码
- 该证据最多能支持什么
- 替代解释或反例
- 置信度及原因

## 2. 第一阶段：全景扫描

目标是建立足以选择深挖对象的地图，不是穷举全部功能。

### 2.1 游戏快照

记录类型、平台、版本、典型会话时长、目标玩家、玩家身份/幻想、核心压力、成功失败和主要差异。

### 2.2 体验命题与反支柱

体验支柱必须能转成玩家行为标准。标注它来自开发者，还是研究者根据成品反推。再写一条 Anti-Pillar，说明游戏主动不追求什么。

### 2.3 核心动词

区分：

- 核心动词：不执行就无法进行主要玩法。
- 支撑动词：准备、恢复或改变核心行为条件。
- 表达动词：体现身份、风格或叙事选择。
- 管理动词：配置、整理、升级、交易和规划。

不要只写按钮。“射击”是动作，“判断暴露风险后选择压制还是转移”才是设计问题。

### 2.4 三层循环

| 层级 | 典型尺度 | 研究问题 |
|---|---|---|
| 瞬时循环 | 5—30 秒 | 感知、判断、执行和反馈怎样连续发生 |
| 遭遇/单局 | 数分钟到一局 | 局势如何建立、升级、结束和结算 |
| 跨局/长期 | 多局或多小时 | 知识、资源、能力、身份和内容进度如何积累 |

Game Loop 节点写动词；Resource Flow 节点写名词。

### 2.5 系统与资源

对每个相关系统标记 `核心/支撑/约束/表现`，记录上游输入、下游输出和依赖。资源不仅是金币和材料，还包括时间、注意力、信息、位置、安全、行动机会、风险和控制权。

检查：

- Sources/Sinks 是否制造真实取舍。
- 是否存在正反馈、负反馈、滚雪球和恢复阀门。
- 哪个资源是瓶颈，哪个只是伪资源。
- 精通后是否进入稳定平台，导致压力消失。

### 2.6 学习、挑战、失败和节奏

区分难度大小与难度成分：推理、操作、随机、局外资源、主题承受、耐力、人际技能、局内资源。记录失败是立即结束、渐进恶化还是可恢复，以及失败后玩家得到知识、路线、资源还是只有时间损失。

## 3. 选择深挖对象

候选项按 1—5 分评分：

```text
深挖优先级 = 核心性 + 差异性 + 不确定性 + 迁移价值 + 证据缺口 - 调研成本
```

通常选择一个主对象，只附带一到两个强耦合系统。不要因为某系统复杂就自动深挖；优先研究最可能改变设计决定的未知。

## 4. 第二阶段：深度拆解

### 4.1 限定研究单元

使用一次攻击交换、一轮牌序、一场标准遭遇、一次发现线索并选择目的地等可观察单元。记录前置资源、玩家知识和目标。

### 4.2 逐拍还原

对一次完整循环记录：

1. 触发与前置状态。
2. 玩家感知的信息与隐藏信息。
3. 玩家试图预测什么。
4. 真实可选行动与支配策略风险。
5. 操作、时机和精度要求。
6. 系统结算顺序与状态变化。
7. 即时、延迟和隐性反馈。
8. 局势、长期成长或玩家理解的后果。
9. 结果怎样生成下一问题。

### 4.3 决策质量

检查选项是否在目标、风险、成本、时机或风格上真正不同；信息是否足够但不过载；决定是否可撤销；后果何时显现；深度来自更多按钮还是简单规则组合。

### 4.4 系统耦合与涌现

记录上游输入、下游输出、强耦合点、反馈环、中断器、协同、冲突、替代和稳定平台。系统数量多不等于涌现；一致规则、清楚可供性和跨系统可作用性才使玩家能够实验。

### 4.5 学习与精通

建立五级阶梯：

1. 操作与基本规则。
2. 信息识别与因果理解。
3. 局部策略和资源预算。
4. 系统组合、预测和例外处理。
5. 风格表达、主动风险选择和规则利用。

同时记录新手与高手看见的选择空间差异，以及随机试按、遗忘目标、无法解释失败等认知过载症状。

### 4.6 迭代和生产约束

尽量恢复 `目标 → 方案 → 实测现象 → 诊断 → Cut/Pivot → 新结果与代价`。分析内容生产、动画、配音、关卡、服务器、运营和团队协作是否是方案成立的前置条件。

## 5. 竞品与迁移

竞品必须围绕同一玩家问题比较，而不是比较功能数量。统一对照目标玩家、体验承诺、核心决策、循环、资源张力、挑战成分、学习路径、失败恢复、系统涌现、主要取舍和生产要求。

每条迁移建议写成 Transfer Card：

- 原游戏问题
- 实现机制
- 因果解释
- 证据与置信度
- 可迁移原则
- 前置条件
- 失效边界
- 最小原型
- 通过标准
- 停止或转向标准

## 6. 常见错误

1. 按菜单顺序抄功能，没有因果链。
2. 把高赞、高粉或高段位自述当成机制证据。
3. 只看高手，忽略新手学习与信息负荷。
4. 把开发者意图当成玩家效果。
5. 把社区声音当总体分布。
6. 忽略版本、平台、模式与难度差异。
7. 没有反例，只收集支持初始观点的材料。
8. 迁移表皮功能，没有迁移前置条件和取舍。
9. 输出结论但没有最小验证实验。
