## 1. 社区材料能回答什么

玩家攻略适合发现：

- 玩家怎样命名和理解系统。
- 哪些策略、误区、操作难点和非预期用法反复出现。
- 高手如何压缩决策、识别信息和控制风险。
- 版本变化后哪些旧认知仍在传播。
- 不同玩家类型为何产生相反体验。

玩家攻略通常不能单独证明：

- 某观点代表总体玩家比例。
- 某机制一定是开发者原始意图。
- 点赞更高的打法一定更有效。
- 相关性就是因果关系。

将社区来源视为“问题发现器、策略样本和心智模型证据”，再用直接游玩、规则资料、录像或数据验证。

## 2. 关键词与分层采样

### 2.1 建立关键词矩阵

组合：

```text
游戏名/俗称/英文名
× 系统、角色、武器、地图、流派、模式
× 攻略、机制、进阶、误区、测试、数据、配装、复盘、速通、上分
× 当前版本号、赛季名、补丁日期
```

每条查询保存原始关键词、平台、排序方式、时间窗、采集时间和搜索结果位置。

### 2.2 每个平台至少分四层

| 样本层 | 目的 | 风险 |
|---|---|---|
| 热门/高互动 | 找主流叙事和成熟攻略 | 放大算法和既有流量优势 |
| 最新 | 找当前版本变化 | 质量波动、结论尚未稳定 |
| 中长尾 | 找反例、冷门流派和被压低内容 | 需要更多人工筛选 |
| 指定作者 | 跟踪专家连续观点 | 容易产生个人偏差 |

不要用首页推荐流替代关键词搜索。推荐流受账号历史、地域、关系和即时热点影响，难以复现。

### 2.3 两阶段样本量

全景扫描先追求覆盖而不是数量：每个关键查询在每个平台抽取少量热门、最新和中长尾材料，记录饱和度。深挖阶段只扩展与核心玩法命题直接相关的内容，并加入反例查询，例如“为什么不好用”“反制”“失误”“已过时”。

样本量不能自动解决系统偏差；优先确保不同排序、玩家阶段、立场和版本都有覆盖。

## 3. 高阶玩家与观点可信度

### 3.1 作者可信度等级

| 等级 | 可接受依据 |
|---|---|
| A | 可验证比赛成绩、官方排行榜、公开段位页、完整比赛/对局记录、官方教练或开发身份 |
| B | 长期专精同一游戏，持续提供完整录像、测试条件、数据和可复现过程 |
| C | 稳定攻略创作者，但玩家水平或测试过程缺少外部验证 |
| D | 普通评论、二手转述、身份和过程不可验证 |

只使用公开、与研究问题有关的证据验证身份。不要采集真实姓名、联系方式、IP属地、关系链或其他不必要个人信息。

### 3.2 观点证据强度

| 等级 | 标准 |
|---|---|
| S | 当前版本可重复验证，附录像、帧数、数值或明确复现步骤 |
| A | 多个彼此独立的可信来源在相同条件下得出一致结论 |
| B | 单个可信作者给出完整条件、过程和因果解释 |
| C | 多名玩家表达相似体验，但缺少机制验证 |
| D | 单条评论、情绪判断、无条件结论或无法复现 |

作者等级与观点等级必须分开。顶尖玩家也可能错误解释原因；普通玩家也可能提供可复现的高质量反例。

### 3.3 互动数据的使用边界

点赞、收藏、投币、播放和评论量主要说明内容传播和受众响应，不直接说明玩法结论正确。不同平台量级不能直接相加或横向比较。可以在同平台、同时间窗、相近内容形态中做辅助排序，但必须保留发布时间和曝光差异。

## 4. 平台差异

七个平台是候选来源池，不是必须平均分配的七个样本桶。先依据研究问题选择平台，再在平台内做热门、最新、中长尾和指定作者分层；跨平台转载不能算独立证据。

### 小红书

- 图文步骤、配装清单和评论补充较丰富。
- 搜索结果和 URL 常依赖 `xsec_token`；内容可能随登录态和地域变化。
- 图片可能承载主要结论，正文采集后仍需 OCR。

### 抖音

- 适合发现高频技巧、失败片段和即时版本话题。
- 短视频剪辑常省略前置条件，需要追溯完整对局或交叉验证。
- 热门与搜索排序变化快，记录采集时间和查询位置。

### 快手

- 适合发现短视频操作示范、实用技巧和不同圈层玩家的表达。
- 片段化内容同样容易缺失配装、段位、模式和版本条件；把演示动作与作者解释分别编码。
- 不把点赞、评论等互动量与抖音直接横向比较；先在同平台、相近发布时间和内容形态内排序。

### B站

- 长视频、逐帧演示、复盘和弹幕能提供较完整的过程证据。
- 标题与简介通常不足以代表视频主张，应保存字幕/转写时间戳。
- 投币、收藏和播放反映不同互动动机，不合并成单一“质量分”。

### 微博

- 适合追踪补丁发布后的即时讨论、争议爆发和版本认知变化。
- 短文本、转发和截断正文容易丢失论证条件；必要时获取全文并回到原始来源。
- 同一消息常被转述或搬运，按原始 URL、发布时间和文本相似度建立传播簇，不把转发当独立佐证。

### 贴吧

- 长帖、楼中楼和多年累积讨论适合寻找机制争辩、反例、冷门流派与版本历史。
- 楼层可能跑题，结论必须保留主帖、楼层、父回复和发布时间关系。
- 旧攻略在搜索结果中持续可见；按补丁或赛季切分，不把跨版本共识混成当前结论。

### 知乎

- 回答、文章和视频适合寻找较完整的系统解释、设计分析和因果假设。
- 表达完整不等于机制正确；把作者资历、引用材料、复现过程和观点证据分别评分。
- 问题可能跨越多年，回答的编辑时间和游戏版本必须单独核对。

### 小黑盒

- 玩家身份、游戏库和垂直社区可能提供更强的游戏语境。
- 当前没有成熟、热门、持续维护的通用攻略采集项目；优先人工检索＋URL登记＋半自动提取。
- 如制作适配器，只处理公开 Web 内容，并把它与其他平台隔离，允许单独失效。

建议标准化为：

```yaml

```

原始响应保存为不可修改快照；标准化数据只保存分析所需字段。删除 Cookie、令牌、手机号、精确位置和无关个人资料。

## 6. 分析与质量控制

### 6.1 先去重，再让模型编码

按平台内容 ID、规范化 URL、标题/正文相似度和视频指纹去重。转载内容不算独立证据；保留传播关系但降低独立性权重。

### 6.2 原子化主张

将一条攻略拆成多个主张：条件、操作、机制解释、结果、版本和例外。禁止让大模型只输出“总体情绪”或词频图后直接形成玩法结论。

### 6.3 反例优先

对每条关键结论主动搜索：反制、失败、不同段位、不同平台、旧版本和不适用玩家。若只找到支持材料，把结论保留为低/中置信度。

### 6.4 可追溯交付

每条结论保留来源 URL、短摘录或转写时间戳。最终文档不大量复制原文或重新分发受版权保护内容；只保存研究所需的短证据定位和分析。

## 7. 合规和隐私

- 优先官方开放接口、作者主动提供材料和人工导出。
- 仅处理公开内容和必要字段，设置合理频率、并发和停止条件。
- 不绕过验证码、付费墙、访问控制或账号封禁。
- 不将采集账号 Cookie、会话、浏览器用户目录或原始个人信息提交到仓库。
- 在公司、商业或规模化使用前，单独评估平台条款、许可证和法律基础。
