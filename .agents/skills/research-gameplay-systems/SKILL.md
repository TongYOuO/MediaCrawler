# 游戏系统与核心玩法调研

产出可追溯、可证伪、可迁移的玩法研究，而不是功能介绍或社区观点汇编。

## 先读取所需材料

- 开展完整两阶段研究时，读取 [references/research-method.md](references/research-method.md)。
- 采集或评价社区攻略时，读取 [references/community-source-quality.md](references/community-source-quality.md)。
- 使用本仓库 MediaCrawler 时，读取 [references/mediacrawler-operations.md](references/mediacrawler-operations.md)。
- 需要了解本次技术选型实例时，读取 [references/example-community-source-stack.md](references/example-community-source-stack.md)。实例中的活跃度是时间快照，使用前重新核验。
- 创建交付文档时，复制 [assets/gameplay-research-template.md](assets/gameplay-research-template.md)，或运行初始化脚本。

## 工作流

### 1. 冻结研究任务

先明确：

1. 要支持什么设计决定。
2. 游戏、模式、平台、版本和目标玩家。
3. 一个可证伪的主问题和不超过三个子问题。
4. 纳入、排除范围与时间盒。
5. 哪项观察会推翻当前假设。

如果用户没有给出版本或范围，先从公开信息和当前材料中推断最小合理范围，并把假设写进文档。只有选择会实质改变结论时才询问用户。

### 2. 建立研究案例目录

从仓库根目录运行：

```powershell
uv run python .agents/skills/research-gameplay-systems/scripts/init_research_case.py `
  --game "游戏名" `
  --version "版本或赛季" `
  --output "research-cases"
```

脚本拒绝覆盖已有案例。目录包含研究文档、来源登记、证据账本、关键词矩阵和各平台原始数据目录。

### 3. 设计来源与采样

至少组合两类不同来源：

- 直接游玩、录像或可复现实验：说明规则和行为怎样发生。
- 开发者分享、GDC、补丁说明：说明意图、迭代与约束。
- Wiki、规则页、官方数据：核对事实与版本。
- 社区攻略、评论和高阶玩家复盘：发现策略、心智模型、争议和反例。
- 遥测、排行榜或比赛记录：估计频率或验证玩家身份。

不要把首页推荐流当样本框。预先建立“游戏名 × 系统/角色/流派 × 攻略/机制/进阶/误区/测试/复盘”等关键词矩阵，并分别采集热门、最新、中长尾和指定作者样本。

### 4. 第一阶段：快速全景扫描

以小样本快速建立：

- 体验命题和目标玩家幻想。
- 核心动词。
- 瞬时、单局/遭遇、跨局三层循环。
- 系统关系与资源流。
- 学习、挑战、失败、恢复和节奏快照。
- 争议、未知与深挖候选。

按“核心性＋差异性＋不确定性＋迁移价值＋证据缺口－调研成本”选择一个主深挖对象。评分只用于暴露判断，不伪装成客观真理。

### 5. 第二阶段：深度拆解关键玩法

把对象限定为一次可观察过程，例如一次攻击交换、一轮卡牌决策、一场遭遇或一次资源耗尽后的恢复。逐拍记录：

```text
触发 → 感知 → 判断 → 选择 → 执行 → 系统结算 → 反馈 → 后果 → 下一问题
```

同时检查规则与状态、决策质量、系统耦合、学习与精通、挑战成分、失败恢复、节奏中断、受众取舍和迭代历史。

### 6. 编码社区证据

把每条材料拆成最小主张，至少标记：

- `规则事实`
- `可复现操作`
- `玩家解释`
- `数值/版本主张`
- `反例`
- `情绪/偏好`
- `未经验证推测`

将作者可信度与观点证据强度分开。高粉、高赞和段位自述不能替代可验证战绩、完整录像、复现实验或跨来源一致性。

### 7. 综合与交付

每条高影响结论必须包含 Evidence ID、适用条件、版本、来源定位、替代解释和置信度。最终分别给出：

1. 设计理解：它怎样运作，为什么产生这种体验。
2. 竞品判断：围绕同一玩家问题，它选择了什么取舍。
3. 迁移建议：可迁移原则、前置条件、失效边界和最小验证实验。

## 使用 MediaCrawler 的边界

- 只采集公开、与研究问题相关的最小数据；控制频率与并发。
- 不绕过验证码、访问控制或付费/私密内容，不逆向规避平台限制。
- 不提交 Cookie、手机号、原始个人身份或下载媒体到 Git。
- 先检查平台条款、robots、研究目的和适用法律。
- 本仓库许可证限制为非商业学习研究；企业或商业场景先取得授权或改用获准接口。
- 原始 JSONL 只作证据快照；分析前复制到案例目录，保留采集时间、查询词和来源 URL。

## 完成门槛

- [ ] 版本、平台、范围、目标玩家和研究问题明确。
- [ ] 全景阶段有三层循环、系统图和资源流。
- [ ] 深挖对象是可观察、可证伪的玩法问题。
- [ ] 社区样本不是只取热门或首页推荐。
- [ ] 事实、玩家观点、开发者意图和研究者推论分开。
- [ ] 高影响结论有 Evidence ID、反例和置信度。
- [ ] 至少两类独立来源支持核心结论，或明确降低置信度。
- [ ] 迁移建议写明前置条件、失效边界和最小验证。
- [ ] 原始账号凭证、个人信息和受版权保护的大体量内容未进入提交。
